# Working on this repository

An audited catalog of open methodological problems in target trial emulation, published as a
Quarto site. The catalog is not the point; **the audit trail is the point**. Every claim on the
site carries a verdict and the evidence behind it.

Read `README.md` for the build commands and `methods.qmd` for the published audit protocol.

## House style, enforced everywhere

These are not preferences. Prose is generated by several different agents and the catalog has to
read as one voice.

- **Never use a dash as a sentence connector or parenthetical.** No em dash, no en dash, no
  spaced hyphen, no double hyphen. Use a semicolon, a colon, or a period. Hyphens inside compound
  words, code identifiers, file names and proper names are fine.
- **American spelling**: modeling, standardize, behavior, summarize, dichotomization.
- No hedging filler. An entry states a methodological fact, not a complaint.
- Do not write "this paper" or "the authors". An entry describes the state of the field, not a
  reading of one document.
- **Never invent a citation.** An invented citation is the worst thing that can go in this
  repository and the easiest for a reader to catch. If a work cannot be resolved, say so and cite
  nothing.

## Invariants that will silently break the site

1. **The category code prefixes the problem id, which prefixes the filename.**
   `render_site.mjs` writes `problems/${id}-${slugify(title)}.qmd`, and each category page globs
   `../problems/${code}-*.qmd`. An entry whose `id` prefix disagrees with its `category` still
   renders as a page but vanishes from its category listing: present but unfindable. There is a
   test for this; keep it passing.
2. **Recategorizing means renaming, and filenames are published URLs.** Fix the 18 codes before
   entries exist, not after.
3. **`styles.scss` must appear in both the light and dark theme lists** in `_quarto.yml`. Quarto
   emits one stylesheet per mode, so a rule listed only under light does not exist in dark.
4. **Verdict, priority and maturity values are CSS class names**, produced by `slugify()` of the
   field value. A new enum value with no matching rule renders unstyled.
5. **A navbar entry pointing at a file that does not exist fails the render.** `chronology.qmd`
   and `studies.qmd` are written conditionally, so they join the navbar only once generated.

## The adjudication rule

`build/adjudicate.mjs` turns auditor opinions into the published verdict. Two design principles:

- **An unsubstantiated "solved" vote is not evidence.** It is downgraded, not counted (`R0`).
- **Evidence beats votes.** A lone dissenter holding an unrebutted verbatim quote is not silently
  outvoted by auditors holding opinions.

`INDEPENDENT` must name the auditors that actually run. The sibling ITC project declares a
`solved-hunter` that casts zero opinions, which leaves one guard permanently inert; do not
reproduce that. If you add or remove an auditor, bump `RULE_VERSION` and update the golden tests.

Majority rules carry a **per-problem denominator**: a count must be at least two and at least
half of the independent auditors that returned an opinion on that problem. Coverage is uneven
because auditors run out of quota, so the denominator cannot be the roster size.

## Things that are true and easy to get wrong

- **The `.md` export of the source document lost its citations.** ChatGPT's markdown export
  replaces links with private-use-area tokens (`U+E200`, `turn12search3`) that resolve to
  nothing. The `.docx` keeps the real hyperlinks. Extract from
  `documentation/seed-linked.md`, generated from the `.docx` by pandoc, and consult
  `documentation/audit/seed-citations.json` for the resolved identifiers. Seven of the 35 seed
  references are still unresolved and are marked `"confidence": "none"`; do not cite those until
  someone confirms them.
- **Never convert a source-document citation token into a citation.** If a real author name
  appears in the prose, resolve that name against CrossRef and record the evidence. Otherwise the
  entry carries `source_unsourced: true`.
- **Extract paper text to a file, then read the file.** `pdftotext <path> scratch/<id>.txt`. Do
  not pipe an extraction into your own reply: a long applied review with wide tables comes out as
  tens of thousands of lines of column-shredded text and has derailed a run outright.
- **Build reading output incrementally with a script, one paper at a time.** A single Write call
  carrying a whole batch has stalled with nothing saved.
- **A finding without a verbatim quote and a locator is discarded.** `verify_quotes.py` checks
  every quote against the paper.

## Available auditors

| Auditor | CLI | Lens |
|---|---|---|
| `codex` | `codex exec -m gpt-5.6-sol` | Technical correctness; verifies software claims against pinned source |
| `grok` | `grok --model grok-4.5` | Recency and prior art; inverted prior, web search mandatory |
| `glm` | `ollama` `glm-5.2:cloud` | Third independent lens |

GLM ignores Ollama's `format` schema field on its own; the expected JSON object must also be
restated in the prompt body. Its fenced output parses through `unwrapGrok()` unchanged.

`kimi-k3` is configured for but currently unreachable: Ollama returns `extra usage balance is
empty`. Adding it back is one entry in the auditor list plus a `RULE_VERSION` bump.
